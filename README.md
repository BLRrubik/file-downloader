# file-downloader

Консольная утилита на Go для параллельного скачивания файлов по HTTP с докачкой, ретраями и прогресс-баром.

## Возможности

- **Скачивание сразу нескольких URL** параллельно (каждый файл — в своей горутине).
- **Разбиение файла на чанки** по 100 КБ и скачивание чанков одного файла параллельно (worker pool, до 4 воркеров на файл).
- **Докачка (resume)**: прогресс каждого файла сохраняется в `<имя_файла>.progress` (JSON рядом с файлом назначения). При повторном запуске уже скачанные чанки не перекачиваются.
- **Ретраи**: до 3 попыток на чанк с паузой 2 секунды между ними.
- **Прогресс-бар** на файл (через [mpb](https://github.com/vbauerster/mpb)) с процентом выполнения; при неисправимой ошибке скачивания бар показывает `ошибка` вместо процента.
- **Корректная обработка Ctrl+C**: сигнал `SIGINT` отменяет контекст, все воркеры останавливаются, прогресс перед выходом сохраняется — при повторном запуске скачивание продолжится с прерванного места.
- Скачивание одного файла не блокирует остальные: ошибка (например, 404) по одному URL не останавливает скачивание других файлов из того же запуска.

## Требования

- Go 1.26+
- Сервер, отдающий файлы, должен поддерживать `Range`-запросы (заголовок `Accept-Ranges: bytes`, ответ `206 Partial Content` на запрос с `Range`).

## Установка / сборка

```bash
go build -o bin/downloader ./cmd/downloader
```

## Запуск

```bash
./bin/downloader <директория_назначения> <url1> [url2 ...]
```

Пример:

```bash
./bin/downloader ./downloads http://example.com/file1.zip http://example.com/file2.iso
```

- `<директория_назначения>` — куда сохранять файлы (будет создана, если её нет).
- Дальше — один или несколько URL через пробел.

Имя сохраняемого файла берётся из последнего сегмента URL (всё после последнего `/`).

### Остановка и докачка

`Ctrl+C` во время скачивания корректно останавливает процесс и сохраняет прогресс. Повторный запуск той же командой продолжит скачивание с места остановки (используются `.progress`-файлы рядом с файлом назначения).

## Тестовый файловый сервер (для разработки)

В репозитории есть вспомогательный сервер, раздающий локальную директорию с поддержкой `Range` — удобно для локальной проверки без внешних URL.

```bash
go build -o bin/testserver ./cmd/testserver
./bin/testserver <директория> <порт>
```

Пример:

```bash
./bin/testserver ~/Downloads 8123
# в другом терминале
./bin/downloader ./downloads http://127.0.0.1:8123/file.pdf
```

## Как это устроено

- `cmd/downloader` — точка входа CLI, разбор аргументов, обработка `SIGINT`, инициализация прогресс-бара.
- `cmd/testserver` — локальный HTTP-сервер для тестов (`http.FileServer`).
- `internal/downloader` — основная логика:
  - `Downloader.Download` — параллельный запуск скачивания по всем URL, агрегация ошибок (`errors.Join`).
  - `Downloader.downloadURL` — скачивание одного файла: получение размера через `HEAD`, чтение/создание `.progress`-состояния, разбиение на чанки, worker pool на `errgroup.WithContext` (ошибка любого воркера или отмена контекста останавливают раздачу новых чанков остальным).
  - `internal/downloader/state.go` — сериализация состояния скачивания (`DownloadState`) в JSON-файл `.progress`.

## Известные ограничения

- Размер чанка (100 КБ), число ретраев (3) и число параллельных чанков на файл (4, задаётся в `main.go` при создании `Downloader`) — константы в коде, флагов командной строки для их изменения нет.
- Сервер должен отдавать корректный `Content-Length` и поддерживать `Range`; при `HEAD`-ответе не `200 OK` файл считается недоступным и пропускается с ошибкой.
